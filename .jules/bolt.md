## 2026-04-06 - Prevent N+1 Query Bottlenecks in Data Aggregation
**Learning:** The application has multiple dashboard and analytics endpoints (e.g., arena boss generation, yearly trends) that originally performed individual `SELECT COUNT(*)` queries inside loops over years, subjects, or other categories. This created N+1 query loops that scaled linearly with the number of categories, causing performance degradation as the PyQ dataset grows.
**Action:** Use a single `GROUP BY` query to fetch counts or metrics for all required dimensions simultaneously. Pass the aggregated results to the application layer, either mapping them into an O(1) Python dictionary for subsequent lookups (e.g., in `get_year_trends`), or injecting them as a `precomputed_count` argument to processing functions (e.g., `get_boss_stats`). Also, ensure robust dictionary indexing by defensively handling tuple vs `sqlite3.Row` row objects using `try...except (TypeError, IndexError)`.
