## 2026-03-09 - N+1 Bottleneck in Subject Wise Analytics
**Learning:** The analytics `/api/analytics/subject-wise` endpoint was retrieving metrics (mock test average, answer writing average, and syllabus percentage) by executing 3 database queries *per subject* within a loop over a static list of 6 subjects (resulting in 18 separate queries). This N+1 query pattern creates an unnecessary bottleneck.
**Action:** Replace looped individual queries with aggregated grouped queries (e.g. `GROUP BY subject` and `IN (sub1, sub2, ...)`), calculating metrics for all requested subjects at once. This reduces the DB hit count from 18 to 3 queries, regardless of the number of subjects. Also, always use granular try...except blocks for batched queries so that a single query failure does not skip subsequent queries and zeroes out their results silently.
