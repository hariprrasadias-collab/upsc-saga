## 2024-04-10 - Avoiding N+1 Queries with Iterator Parameters
**Learning:** In the backend routes, particularly `get_year_trends` inside `backend/app/routes/seer.py`, executing individual sub-queries inside a loop (like iterating through each `year` to fetch that year's counts) creates a massive N+1 bottleneck and impacts response times significantly.
**Action:** Instead of iterating and querying individually, aggregate data using a single `GROUP BY` query (e.g., `SELECT year, subject, COUNT(*) FROM ... GROUP BY year, subject`), and handle the organization and grouping locally using Python's `collections.defaultdict`. This turns O(N) database trips into O(1) database trips. Ensure that `unique_subjects` gets sorted while creating the response data list to guarantee a consistent order of output for frontend UI elements like Charts.
