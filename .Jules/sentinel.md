## 2024-05-24 - SQL Injection in Dynamic Limits
**Vulnerability:** Found a SQL injection vulnerability where a `limit` parameter from JSON input was directly interpolated into a SQL query string (`query += f" LIMIT {limit}"`).
**Learning:** Even simple integer parameters like `limit` or `offset` can be vectors for injection if not validated or parameterized. Developers often overlook these believing they will always be numbers.
**Prevention:** Always cast numeric inputs to their respective types (int/float) and use parameterized queries (`LIMIT ?`) even for standard SQL clauses. Never trust input types from JSON.
## 2024-05-27 - [Fix SQL Injection in PYQ filtering]
**Vulnerability:** SQL Injection in PYQ FTS search filter (`query += f" AND id IN ({','.join(ids)})"`).
**Learning:** Even if `ids` is derived from an internal `rowid` generated by FTS, concatenating them directly into a query is unsafe and violates defensive coding principles.
**Prevention:** Always parameterize `IN` clauses dynamically using `','.join(['?'] * len(ids))` and appending the IDs to the parameter list, regardless of the data source.
