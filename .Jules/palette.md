## 2024-05-23 - Toast Notification Accessibility
**Learning:** Notifications are often invisible to screen readers without proper roles. Using `role="alert"` for errors (assertive) and `role="status"` for info (polite) ensures users are notified at the right urgency level.
**Action:** Always categorize toast notifications by urgency and apply corresponding `aria-live` regions, while ensuring close buttons have clear labels.
## 2026-03-17 - Adding accessibility tags to icon-only buttons
**Learning:** Standard UI components, particularly those imported or adapted from common sources, frequently lack essential accessibility attributes like `aria-label` for icon-only interactive elements. When components use emojis or unlabelled icons as buttons without explicit labels, screen readers may read the unicode value of the icon/emoji or fail to announce its purpose. Moreover, the icon itself should be hidden from screen readers using `<span aria-hidden="true">`. Providing an explicit descriptive `aria-label` directly on the button ensures assistive technologies accurately announce the element's intent.
**Action:** When auditing or implementing new interactive UI components that feature icon-only buttons (such as settings gears, history icons, edit pencils, or save checkmarks), always inspect them to verify an `aria-label` is present on the button element and the visual icon text/emoji is wrapped in an `aria-hidden="true"` element.
