## 2025-03-03 - [Optimized syllabus progress trend to eliminate N+1 queries]
**Learning:** The `get_progress_trend` function in `backend/app/routes/analytics.py` iteratively fetched `syllabus_topics` data `days + 1` times (via `SELECT COUNT(*)` queries). However, because the `syllabus_topics` table only tracks current topic status and lacks a historical tracking mechanism, these inner-loop queries always returned the same value.
**Action:** Lift repeated logic out of loops when the underlying data tables do not support historical/time-series filters, calculating the value once beforehand to transform an O(N) database query scenario into O(1).
## 2025-02-18 - [N+1 Optimization in Analytics Service]
**Learning:** N+1 queries in loops analyzing weak areas based on subjects can be optimized heavily by doing a bulk fetch using `IN` query.
**Action:** Look out for multiple fetchalls in loop and optimize them into bulk fetches.
